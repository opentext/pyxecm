    SAP S/4HANA APIs Required by This Module¶

    This page lists everything that must be activated/authorized in the target S/4HANA system for the pyxecm_customizer.sap.SAP class to work. It is a checklist for S/4HANA Basis/Gateway administrators, derived from the service registry in sap.py (SAP_ODATA_SERVICES).

    Use SAP.check_odata_apis() to verify the status of all services below against a live system - it reports exactly which of the steps below is still missing per service.

    General activation steps (apply to every OData service)¶

    1. /IWFND/MAINT_SERVICE (OData V2) or /IWFND/V4_ADMIN (OData V4): activate / publish the service for the relevant backend system alias.
    2. V2: "Add Service" -> backend system alias (e.g. LOCAL) -> technical service name (e.g. API_MAINTENANCEORDER) -> "Get Services" -> select the version(s) (e.g. 0001, 0002) -> "Add Selected Services".
    3. V4: "Publish Service Groups" for the service group (e.g. API_PURCHASEORDER_2).
    4. SICF: the ICF node of the service must be active (/sap/opu/odata/sap/<service> for V2, /sap/opu/odata4 for V4).
    5. PFCG: the calling user needs authorization object S_SERVICE for the service (role menu entry of type IWSG), plus the business authorizations for the underlying transaction (e.g. as for IW31 to create maintenance orders).
    6. /IWFND/GW_CLIENT: GET /sap/opu/odata/sap/<service>/$metadata (or the V4 equivalent) should return HTTP 200 as a smoke test.

    Troubleshooting: /IWFND/ERROR_LOG, SU53, and the system log (SM21).

    "No System Alias found for Service" (/IWFND/CM_COS/064, HTTP 500)¶

    SAP.check_odata_apis() reports state=error with a message like [/IWFND/CM_COS/064] No System Alias found for Service '<technical name>' and user '<user>' when a service has been registered in /IWFND/MAINT_SERVICE but has no backend system alias assigned to it - a step further than "not activated" (403), but still unusable. This typically happens when the service was added through a route other than the normal "Add Service" wizard in step 1 above (e.g. transport import, or a different Fiori content activation report), which skips the alias assignment. To fix it in /IWFND/MAINT_SERVICE:

    1. Filter/find the entry for the technical service name (e.g. API_MAINTNOTIFICATION) in the service list.
    2. Select its row and open the "SAP System Alias" assignment dialog (toolbar button / context menu on the row - exact label depends on the SAP_GWFND release).
    3. Add the same backend system alias that the already-working services use (e.g. LOCAL - check the alias of API_MAINTENANCEORDER, which is active, for the correct value in this system) and mark it as default if prompted.
    4. Save, then re-run SAP.check_odata_apis() to confirm the service moved to active.

    OData services¶

    The BO Type column lists the SAP business object type (BOR object type, transaction SWO1) of the main entity of each service - e.g. the type to use for business workspaces and business object references in Extended ECM. All types were checked in the S/4HANA reference system; "-" means there is no BOR object type for the entity.

    The business object types that business workspaces are typically linked to are also available in code: SAP_BUSINESS_OBJECT_TYPES in pyxecm_customizer.sap_models (name and key structure), and get_sap_key_fields() converts a business object ID (SAP's internal format, e.g. "49000001232026") into the key fields the OData APIs expect (e.g. ("4900000123", "2026")).

    ¹ BUS0008001 is the BOR object type "Plant storage area" - the storage location of a plant.

    RFC channel (SAP.call())¶

    For RFC/BAPI based calls (used e.g. for custom Z function modules or standard BAPIs such as BAPI_USER_CREATE1), OData activation is not relevant. Instead:

    • SM59: an RFC destination (or direct application server connection) must be reachable with the configured ashost/mshost, sysnr/group, client and user.
    • SU01/PFCG: the RFC user needs authorization object S_RFC for the function group of every RFC/BAPI it calls, and the usual business authorizations for the underlying transaction (e.g. SU01 authorizations for BAPI_USER_*).
    • Gateway: the RFC gateway (SMGW) must allow the connection (gw/acl_mode, secinfo/reginfo ACLs) if calling from outside the SAP network.
    • The SAP NW RFC SDK (proprietary, from SAP) and the pyrfc Python package must be installed on the machine running this module (pip install "pyxecm[sap]" only installs pyrfc, not the SDK itself).

    Verifying activation¶

    from pyxecm_customizer.sap import SAP

sap = SAP(username="...", password="...", base_url="https://s4.example.com:44300", ...)
statuses = sap.check_odata_apis()
for name, status in statuses.items():
    print(name, status.state, status.hint)
