    Error Capture¶

    Most pyxecm methods return None (or False) in case of an error and write the reason to the log. Callers that need the reason (e.g. AI agents or MCP tools) can wrap their calls in a capture_errors() block. Return values and logging do not change.

    from pyxecm import ErrorCategory, capture_errors

with capture_errors() as errors:
    node = otcs.create_item(parent_id=4711, item_name="Contracts", item_type=otcs.ITEM_TYPE_FOLDER)

if errors.root_cause and errors.root_cause.category == ErrorCategory.ALREADY_EXISTS:
    ...
elif node is None:
    raise RuntimeError(errors.to_agent_message(fallback="Failed to create folder"))

    Errors are collected as PyxecmError objects - one subclass per module (OTCSError, OTDSError, ...), so isinstance() or errors.of_type(OTCSError) tell where an error comes from. They describe errors and are collected, not raised.

    Each error has a category (e.g. not_found, permission_denied, already_exists), a severity matching the log level (debug is used for failures the code expects, like a lookup that checks if an item exists), the HTTP status_code, the server_message returned by Content Server and the method and url (without query string) of the failed REST call.

    ErrorCollector.root_cause ignores debug records (unless there is nothing else), prefers records with a known category and takes the most recent one.

    The collector is stored in a context variable: it works in the current thread and in asyncio tasks, but threads must be started with contextvars.copy_context().run to report into it.

    Errors are recorded by all API classes with their own error class: OTCS (OTCSError), OTDS (OTDSError), OTAWP, OTAC, OTCA, OTKD, OTMM, OTPD, AVTS and CoreShare (OTAWPError, ... CoreShareError). In pyxecm_customizer, the SAP class records SAPError (from pyxecm_customizer.sap import SAPError) - in addition to its existing last_error property, which is unchanged.

    Recording errors in pyxecm code¶

    The logger of these classes is a ReportingLogger (set up with ReportingLoggerAttribute): it behaves like a normal logging.Logger, but its error() and warning() methods also accept report=True. Use it where a method gives up and the message explains why - typically right before return None / return False:

    if not response:
    self.logger.error("Volume type -> %s not found!", str(volume_type), report=True)
    return None

    Add category=ErrorCategory.... if the message text does not tell the reason clearly. Don't use report=True for messages that don't explain a failure of the method, like retry messages or warnings the method recovers from. Failed REST calls are recorded by do_request() automatically (it calls record_request_error() at its final failure exits).

    A new API class gets the same behavior with its own error class in errors.py and logger = ReportingLoggerAttribute(default_logger, error_class=MyError) as class attribute.

    errors ¶

    Structured error capture for pyxecm API calls.

    Most pyxecm methods return None (or False) in case of an error and only write the reason to the log. Callers that need the reason - e.g. AI agents or MCP tools that have to tell the user why something failed - can wrap their calls in a capture_errors() block. All errors recorded inside the block are collected as structured error objects (OTCSError, OTDSError, ... - all subclasses of PyxecmError). Return values and logging are not affected:

    from pyxecm import capture_errors

with capture_errors() as errors:
    node = otcs.create_item(parent_id=4711, item_name="Contracts", item_type=0)

if node is None:
    print(errors.to_agent_message(fallback="Failed to create folder"))

    Outside of a capture_errors() block recording is a no-op.

    The collector is stored in a context variable. It is visible in the current thread and in asyncio tasks created inside the block, but NOT in threads that are started without copying the context (use contextvars.copy_context().run for that).

    def to_agent_message(self) -> str:
    """Return a concise description of the error that can be shown to an agent or user.

    It does not include the URL.

    Returns:
        str:
            The error description including server message and category.

    """

    text = self.message
    if self.server_message and self.server_message not in text:
        text = "{}: {}".format(text, self.server_message) if text else self.server_message

    details = ["category: {}".format(self.category)]
    if self.status_code is not None:
        details.append("HTTP status: {}".format(self.status_code))

    return "{} ({})".format(text, ", ".join(details))

    def __init__(self, max_errors: int = DEFAULT_MAX_ERRORS) -> None:
    """Initialize the collector.

    Args:
        max_errors (int, optional):
            The maximum number of records to keep. Older records are dropped.

    """

    self._errors: deque[PyxecmError] = deque(maxlen=max_errors)
    self._lock = threading.Lock()
    self._dropped = 0

    root_cause property ¶

    root_cause: PyxecmError | None

    Return the record that most likely explains why the operation failed.

    High-level methods often call other methods internally and may log follow-up errors (like "Failed to create item") after the real cause (like the server error of the REST call) - or they use an expected failure (like a lookup that finds nothing) as part of their logic. So the root cause is determined like this:

    1. Ignore DEBUG records (expected failures) unless there is nothing else.
    2. Prefer records with a known category over ErrorCategory.UNKNOWN.
    3. Among those, take the most recent one.

    def add(self, record: PyxecmError) -> None:
    """Add a record to the collector.

    Args:
        record (PyxecmError):
            The record to add.

    """

    with self._lock:
        if self._errors.maxlen is not None and len(self._errors) == self._errors.maxlen:
            self._dropped += 1
        self._errors.append(record)

    ReportingLogger ¶

    ReportingLogger(
    logger: Logger,
    error_class: type[PyxecmError] = PyxecmError,

    Logger proxy whose error() and warning() can also record the message.

    Behaves like the wrapped logging.Logger - all other attributes and methods (debug(), info(), getChild(), addFilter(), ...) are passed through. In addition, error() and warning() accept these keyword arguments:

    • report (bool) - if True, the message is also recorded for an active capture_errors() block (as an instance of error_class). Use it where a method gives up and the message explains why. Recording does not depend on the log level.
    • category (ErrorCategory | None) - the error category if the message text does not tell it clearly. Only used with report=True.
    self.logger.error("Volume type -> %s not found!", volume_type, report=True)

    def extract_server_message(response_text: str | None) -> str | None:
    """Extract the error message from the body of an error response.

    OpenText REST APIs return errors as JSON like {"error": "..."} (sometimes
    with additional "errorDetail"). HTML responses (e.g. from a proxy) are ignored.

    Args:
        response_text (str | None):
            The body of the HTTP response.

    Returns:
        str | None:
            The error message or None if the body has no recognizable error message.

    """

    if not response_text or response_text.lstrip().startswith("<"):
        return None

    try:
        body = json.loads(response_text)
    except ValueError:
        # Plain text error responses are used as they are (but not unlimited):
        return response_text.strip()[:1000] or None

    if not isinstance(body, dict):
        return None

    for key in ("error", "errorMessage", "message", "error_description"):
        value = body.get(key)
        if isinstance(value, str) and value:
            detail = body.get("errorDetail")
            if isinstance(detail, str) and detail and detail not in value:
                return "{}; {}".format(value, detail)
            return value
        if isinstance(value, dict):
            # Some APIs nest the error: {"error": {"message": "..."}}
            nested = value.get("message") or value.get("description")
            if isinstance(nested, str) and nested:
                return nested

    return None

    @contextmanager
def capture_errors(max_errors: int = DEFAULT_MAX_ERRORS) -> Generator[ErrorCollector]:
    """Collect all errors recorded by pyxecm inside the with-block.

    Blocks can be nested - an error is recorded in all active collectors.

    Args:

        ErrorCollector:
            The collector with the recorded errors.

    """

    collector = ErrorCollector(max_errors=max_errors)

    try:

    finally:

            _active_collectors.set(tuple(c for c in _active_collectors.get() if c is not collector))

    def record_error(
    message: object,
    *args: object,
    category: ErrorCategory | None = None,
    severity: ErrorSeverity = ErrorSeverity.ERROR,
    error_class: type[PyxecmError] = PyxecmError,
    status_code: int | None = None,
    server_message: str | None = None,
    method: str | None = None,
    url: str | None = None,
) -> PyxecmError | None:
    """Record an error in all active collectors.

    This is a no-op if no capture_errors() block is active. It never raises
    an exception, so it cannot change the behavior of the calling code.

    Args:
        message (object):
            Description of what failed. Can be a %-style format string for args.
        *args (object):
            Arguments for a %-style format string in message.
        category (ErrorCategory | None, optional):
            The category. If None, it is determined from status code and texts.
        severity (ErrorSeverity, optional):
            The severity (log level) of the error.
        error_class (type[PyxecmError], optional):
            The class of the recorded error - the one of the recording module, e.g. OTCSError.
        status_code (int | None, optional):
            The HTTP status code if the error comes from a REST call.
        server_message (str | None, optional):
            The error message returned by the server.
        method (str | None, optional):
            The HTTP method of the failed REST call.
        url (str | None, optional):
            The URL of the failed REST call. Query string and fragment are removed.

    Returns:
        PyxecmError | None:
            The recorded error or None if nothing has been recorded.

    """

    collectors = _active_collectors.get()
    if not collectors:
        return None

    try:
        text = format_log_message(message, args)
        if category is None:
            # For REST call errors only the server message is used to determine the
            # category - the message describes the operation (like "Failed to assign
            # permission") and not the reason:
            category_text = server_message if status_code is not None or server_message else text
            category = categorize_error(status_code=status_code, text=category_text)
        record = error_class(
            message=text,
            category=category,
            severity=severity,
            status_code=status_code,
            server_message=server_message,
            method=method,
            url=sanitize_url(url),
        )
        for collector in collectors:
            collector.add(record)
    except Exception:  # recording must never break the calling code
        return None

    return record

    Used by the do_request() methods of the pyxecm classes. This is a no-op if no
    capture_errors() block is active and it never raises an exception.

    Args:

        method (str):
            The HTTP method of the REST call.

            The URL of the REST call. Query string and fragment are removed.

    if not is_capturing():
        return

    # the text of a broken (streamed) response could raise an exception:

        server_message = extract_server_message(response.text) if response is not None else None
    except Exception:  # recording must never break the REST call
        status_code = server_message = None

    record_error(
        message or "{} request failed".format(method),
        category=category,
        severity=severity,
        error_class=error_class,
        status_code=status_code,
        server_message=server_message,
        method=method,
        url=url,
